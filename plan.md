## Are the console errors relevant?
Yes — they are directly relevant and likely the root cause.

From the screenshot, key errors are:
1. `Access to script .../games/gold-miner/main.js ... from origin 'null' has been blocked by CORS policy`
2. `Failed to load resource: net::ERR_FAILED (main.js)`
3. `Unsafe attempt to load URL ... Domains, protocols and ports must match.`

### Why this happens
- The iframe uses sandbox without `allow-same-origin` (required by AGENTS.md), which gives the game document an **opaque origin** (`null`).
- Gold Miner loads runtime via `<script type="module" src="./main.js"></script>`.
- **Module scripts use CORS fetching semantics**; when fetched from an opaque origin, requests commonly fail unless server/CORS behavior explicitly allows it.
- Result: HTML loads, but `main.js` does not execute, so canvas stays blank (exact screenshot symptom).

So this is not a fake warning — this is the likely functional break.

## Constraints to respect
From AGENTS.md in repo root:
- Keep iframe sandbox as `allow-scripts allow-pointer-lock`.
- **Do not** add `allow-same-origin`.
- Keep `referrerPolicy="no-referrer"`.

## Recommended implementation direction
Use an iframe bootstrap document with inline classic script that loads game runtime code from same fetched source, avoiding module-script CORS blockage under opaque origin.

### Option A (recommended): blob/bootstrap HTML generated by host
1. In `PlayPage.tsx`, instead of direct `src=/games/<id>/index.html`, fetch game entry HTML text.
2. Rewrite/normalize it into a bootstrap doc that:
   - preserves existing canvas/DOM shell,
   - replaces `<script type="module" src="./main.js">` with inline loader strategy.
3. Fetch `main.js` text from host context, then inject it into iframe as inline script (or transpile wrapper) so no module network fetch occurs from opaque origin.
4. Set iframe `src` to `blob:` URL generated by host and revoke old object URLs on unmount/update.

### Option B: convert game entry/runtime to non-module classic script
- Move Gold Miner runtime and imports to bundled non-module output, then reference via classic `<script src="...">`.
- Larger refactor, probably higher risk.
